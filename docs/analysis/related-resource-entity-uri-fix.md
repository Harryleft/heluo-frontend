# 相关资源“分片标题”修复记录

## 问题现象
- 图书详情页的“相关资源”栏目出现大段向量分片文本（或分片编号），可读性差。
- 用户期望展示实体级结果（人物/诗文/图书/古籍等），并可通过实体 URI 跳转。

## 根因
- 向量检索返回的是分片文档，`title` 可能来自 `text_norm` 或分片标识。
- 统一搜索聚合阶段在标题选取时，未对“分片文本/分片编号”做过滤。
- 当无法取到干净实体名时，前端最终展示了分片化内容。

## 本次修复
- 在 `server/src/app.js` 新增标题净化规则：
  - 过滤“来源：...”类文本、超长句、HTML 片段、`片段`字样、纯编号样式。
- 增加 URI 样式标题过滤：
  - `"/person/17170"`、`"/processed/.../*.json"` 这类路径文本不再作为展示标题。
- 为 `GET /api/v1/search` 增加实体标题兜底：
  - 优先使用干净标题；
  - 若不可用，则基于实体类型推导主文档候选路径（例如 `person -> /processed/entities/person/{id}.json`）继续反查；
  - 仍不可用时，回退 `未命名条目`，不再回显 URI。
- 保留实体 URI 归一化逻辑，确保跳转目标是实体级 URI。

## 验证结果
- 定向测试通过：`tests/server/api/v1Search.integration.test.ts`
- 新增回归用例：`标题为 URI 样式时应继续反查实体名称，避免回显链接文本`
- 类型检查通过：`npm run -s typescript`
- 预期表现：详情页“相关资源”显示实体名称（可点击），不显示 URI 文本。
