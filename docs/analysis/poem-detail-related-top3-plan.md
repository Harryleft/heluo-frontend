# 详情页相关资源向量推荐方案

## 背景
原“关联资源”依赖详情接口返回的 `internalLinks`，来源不统一、类型覆盖不全，且诗文场景曾被限制为仅 3 条诗文，无法满足“跨人物/图书/诗文/古籍等对象统一推荐”的需求。

## 目标
- 统一命名：侧栏标题由“关联资源”改为“相关资源”。
- 统一策略：详情页相关资源改为向量检索驱动（`mode=vector`）。
- 统一范围：推荐池覆盖全对象类型（人物、图书、诗文、古籍、地点、概念等）。
- 统一数量：每次展示 3-5 条（实现上上限 5，最少按实际命中显示）。

## 方案
```mermaid
flowchart TD
  A[详情页标题/摘要/部分内部链接标签] --> B[构造向量查询文本]
  B --> C[/api/v1/search?mode=vector&page=1&pageSize=12]
  C --> D[过滤当前详情自身 URI]
  D --> E[按 URI 去重]
  E --> F[截取前 5 条]
  F --> G[渲染 相关资源 卡片]
  G --> H[仅展示 标题 + 超链接]
```

## 边界处理
- 向量接口失败：展示“相关资源加载失败，请稍后重试”。
- 命中不足：展示实际条数，不强制补齐。
- 自身去重：当前详情 URI 不参与推荐。
- 数据去重：同 URI 仅展示一次。

## 性能优化
- 查询降载：相关资源查询文本仅使用“标题 + 摘要片段”，避免被 `internalLinks` 二次变化触发重复检索。
- 请求缩容：`pageSize` 下调到 6，仅满足 3-5 条展示目标。
- 前端缓存：按 `详情 URI + query` 做内存缓存，重复进入同一详情直接复用结果。
- 书籍兜底优化：图书详情跳过 `internalLinks` enrich 阶段，避免无效 N+1 请求。

## 验证点
- 诗文详情：可展示跨类型推荐，不再局限“关联诗文 Top3”。
- 图书详情：仍隐藏外部链接模块，同时出现“相关资源”卡片。
- 古籍详情：外部 IIIF 标注保持不变，并可展示“相关资源”。
