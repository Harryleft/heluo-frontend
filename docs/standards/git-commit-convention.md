# Git 提交规范

从 CLAUDE.md 提取的详细提交规范。本文档为智能体和开发者提供完整的 Git 工作流参考。

---

## 硬性规则（必须）

1. 每当你编辑（修改）任何一个文件后，你必须在开始编辑下一个文件之前，先完成一次 Git 提交。
2. 每一次提交必须只包含且仅包含一个文件的改动。
3. 每完成一个文件后，你必须立刻按顺序执行：
   - `git diff`（核对差异范围）
   - `git status`（确认暂存区只涉及一个文件）
   - `git add <文件路径>`
   - `git commit -m "<提交信息>"`
4. 你禁止在工作区同时保留多个"已修改但未提交"的文件；禁止批量提交。

## 例外情况（仅当）

只有在满足以下任一条件时，才允许一次提交包含多个文件：

- 重命名/移动文件需要配套修改（例如路径更新、import 引用更新等）。
- 机械化改动必须保持同步（例如生成文件必须与源文件保持一致）。
- 构建/依赖系统变更需要同时更新锁文件（例如配置文件与 lockfile 必须匹配）。

当使用例外时，你必须在提交信息末尾追加：`Reason: <原因>`。

## 提交信息格式（必须）

- 使用格式：`<类型>(<文件>): <简短祈使句摘要>`
- 类型可选：feat | fix | refactor | docs | test | chore
- 示例：`fix(src/foo.py): handle empty input`

## 单文件工作流（必须严格按顺序）

对每一个文件：

1. 修改该文件。
2. 执行 `git diff <文件路径>`，确认只包含预期改动。
3. 只暂存该文件：`git add <文件路径>`
4. 执行 `git diff --staged`，确认暂存内容仅来自该文件。
5. 立刻提交（不要等待其它文件）。
6. 执行 `git status`，确认工作区/暂存区干净。

只有完成以上步骤后，才允许开始处理下一个文件。

禁止使用 `git add .` 或 `git add -A`。
必须用明确路径逐个暂存：`git add <文件路径>`。

## 验收门槛（必须）

在继续处理下一个文件之前，你必须确认：

- `git status` 显示工作区干净（或仅存在明确允许的未跟踪文件）。
- `git log -1` 显示最新一次提交信息符合预期，且提交范围仅涉及该文件。
