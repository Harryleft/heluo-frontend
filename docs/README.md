## 使用约定

1. 新文档默认写到对应子目录，不要散落在 `docs/` 顶层。
2. 分析、排查、计划文档优先写入 `docs/analysis/`。
3. 任务追踪、审计、经验沉淀文档优先写入 `docs/tasks/` 或 `docs/reports/`。
4. 代码库架构知识沉淀到 `docs/reference/codebase-qa/`。
5. 归档区文档仅供历史参考，不作为当前开发指引。

## 命名建议

- 分析类文档: `主题-动作-类型.md`
- 报告类文档: `主题-audit/report-日期.md`
- 任务类文档: `主题-todo.md`、`主题-lessons.md`

## 维护要求

- 目录发生变动时，必须同步更新本文件。
- 如果某个目录只是”计划存在”但尚未创建，不要提前写进导航。
- 如果文档发生跨目录迁移，建议在提交信息中注明迁移原因。
