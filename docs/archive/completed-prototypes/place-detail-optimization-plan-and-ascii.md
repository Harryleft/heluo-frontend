# 地理详情界面优化方案与 ASCII 原型（无推荐、无卡片）

## 1. 目标
- 优化地理详情页整体布局与阅读效率。
- 用高德地图 JS API 可视化地理坐标。
- 统一字段命名与文案，让业务语义更准确。
- 页面不展示推荐资源。
- 页面不使用卡片式容器。
- 外部链接基于 `equivalent` 的真实 JSON-LD 数据生成，且展示中文来源名称。

## 2. 需求确认（逐条落地）
| 需求 | 设计决策 |
|---|---|
| 优化地理详情界面 | 使用无卡片分区式布局，桌面双栏，移动端单栏 |
| 坐标可视化 | 通过高德 JS API 渲染点位、支持多点 fitView |
| 调整布局 | 移除左侧“类型：地点”字段；主区展示核心信息 + 历史演变过程 + 地图 |
| 推荐资源 | 地理详情页不展示推荐资源区域 |
| 外部链接处理 | 基于 `equivalent` 生成外链，展示中文来源标签 |
| 字段名优化 | “历史演变”→“历史演变过程”；“字段”→“地理核心信息/基本信息” |
| 历史演变可视化 | 增加“时间线”展示（名称 + 时间） |

## 3. 信息架构（无卡片）
### 3.1 主区（左侧）
1. 地理核心信息（原“字段”）
2. 历史演变过程（原“历史演变”）
3. 地理坐标与地图（高德可视化）

### 3.2 辅助区（右侧）
1. 外部链接（equivalent 生成，中文来源标签）

## 4. 外部链接中文来源映射（建议规则）
| 判定条件（域名/路径） | 展示名称（中文） |
|---|---|
| `vocab.getty.edu` 且含 `/tgn/` | TGN（盖蒂地名词表） |
| `library.sh.cn`（地理词表数据） | 上图地理名词表 |
| 其他来源 | 其他外部来源（可附域名） |

## 5. 字段命名规范（页面文案）
- `字段` -> `地理核心信息`（或 `基本信息`，建议优先“地理核心信息”）
- `历史演变` -> `历史演变过程`
- `类型：地点` 行移除（避免冗余）

## 6. 历史演变过程可视化设计
- 采用“纵向时间线”表达：
1. 时间节点（如：唐代、明代、清代、近现代）
2. 对应名称/别称（中文名、异名）
3. 可选补充说明（来源或事件）
- 无明确时间时：归入“未标注时间”分组。
